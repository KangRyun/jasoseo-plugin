# jasoseo — 자기소개서 작성 파이프라인 (Claude Code 플러그인)

> 회사 하나 조사하고, 문항 뜯어보고, 초안 쓰고, 글자 수 맞추고, 검토하고, 다듬고, 다시 확인하고… 자소서 한 편에 드는 이 반복을 8단계로 정리해 자동으로 돌려주는 Claude Code 플러그인입니다. 특히 **여러 회사에 동시에 지원하는** 신입·인턴 지원자를 위해 만들었습니다.

## 이 플러그인이 대신 해주는 일

여러 회사에 지원하다 보면 매번 똑같은 실수가 반복됩니다. jasoseo는 그걸 막아줍니다.

- **소재 중복** — 같은 프로젝트·같은 수치를 이 문항 저 문항에 또 쓰는 걸 자동으로 잡아냅니다 (같은 숫자가 두 번 나오면 "소재가 부족한 사람"으로 읽힙니다).
- **경험 과장·거짓** — 이력서에 없는 성과, 팀 프로젝트에서 내가 안 한 부분을 "내가 했다"고 쓰는 걸 사실 대조로 걸러냅니다.
- **글자 수 미달/초과** — 문항마다 Python으로 실측해서 제한의 95%를 정확히 채웁니다.
- **회사별 파일 정리** — 회사마다 폴더를 만들고, 폴더 이름에 마감일을 붙여 뭐가 급한지 한눈에 보이게 합니다.
- **읽히는 문체** — 공개된 합격 자소서 1,000여 건의 분포를 기준으로 수치·영문 용어가 너무 빽빽한지, 문장이 기계적인지 검사하고, 기술 배경이 없는 인사 담당자 눈으로 한 번 더 읽힙니다.
- **문항 누락** — 문항이 물은 요소(이유·어려움·배운 점·포부)마다 답하는 문장이 있는지 체크리스트로 확인합니다.

**대신, 못 하는 것도 분명히 말씀드립니다:** 실제 지원 폼에 자동 제출은 하지 않습니다(최종 검토·제출은 본인 몫). 그리고 글자 수 기준이 "공백 포함이냐 제외냐"는 공고에 안 적힌 경우가 많아, 제출 전 지원 폼에서 한 번 확인하시라고 항상 안내합니다.

## 시작하기 전에

- **Claude Code**가 설치되어 있어야 합니다. ([설치 안내](https://docs.claude.com/en/docs/claude-code))
- 본인 **이력서**를 텍스트로 정리해 둔 파일이 필요합니다 (아래에서 설명).

## 설치 (3분)

**1단계 — 플러그인 설치**

GitHub에서 설치 (권장):

```
/plugin marketplace add KangRyun/jasoseo-plugin
/plugin install jasoseo@jasoseo-marketplace
```

직접 클론해서 로컬로 써보려면 (내려받은 폴더 경로를 그대로 사용):

```
/plugin marketplace add ./jasoseo-plugin
/plugin install jasoseo@jasoseo-marketplace
```

**2단계 — 작업 폴더 준비**

지원 준비를 모아둘 폴더(예: `~/취업준비`)를 하나 만들고, 그 안에서 Claude Code를 실행합니다. 이 폴더에 아래 두 파일을 둡니다.

| 파일 | 필수? | 무엇을 담나 |
|---|---|---|
| `이력서.md` | **필수** | 학력·경력·프로젝트·수상·스킬 등 **사실**. 자소서의 모든 소재는 여기서만 가져옵니다. 여기 없는 건 자소서에 안 씁니다. |
| `PROFILE.md` | 선택(권장) | 이력서엔 안 적었지만 자소서엔 쓸 수 있는 것 — 예: "이 프로젝트의 A기능은 팀원이 한 거라 내 성과로 쓰면 안 됨", "여러 회사에 반복해서 쓸 나만의 핵심 컨셉" 등. |

`이력서.md`가 어떤 모습이어야 할지 감이 안 오면, 그냥 이력서 내용을 마크다운으로 편하게 적어두면 됩니다(항목별 제목 + 내용). `PROFILE.md`는 [템플릿](skills/jasoseo/references/profile-template.md)을 복사해 채우세요 — 비워둬도 동작하고, 진행하면서 알게 된 사실이 계속 쌓입니다.

## 사용법

작업 폴더에서 Claude Code를 켜고, **회사명과 직무를 함께** 입력합니다:

```
/jasoseo 삼성전자 데이터엔지니어
```

회사명과 직무는 **둘 다 필수**입니다. 같은 회사라도 직무가 다르면(데이터엔지니어 / 반도체 공정 / 영업) 자소서가 완전히 달라지기 때문입니다. 직무 없이 회사명만 입력하면 Claude가 먼저 직무를 물어본 뒤 진행합니다. 이어서 채용 공고(링크나 이미지)·문항·마감일도 물어보고 8단계를 시작합니다.

특정 단계부터 이어가고 싶으면 맨 끝에 단계 이름을 붙입니다:

```
/jasoseo 삼성전자 데이터엔지니어 리뷰      # 이미 초안이 있고, 전문가 리뷰부터
```

## Codex(OpenAI)에서 쓰기

이 플러그인의 **설치 명령(`/plugin ...`)은 Claude Code 전용**이라 Codex에선 동작하지 않습니다. 하지만 파이프라인 본체는 표준 `SKILL.md`라, Codex의 **Skills** 기능으로 그대로 옮겨 쓸 수 있습니다 (Codex도 `SKILL.md` + `name`/`description` frontmatter 포맷을 씁니다).

**설치 — 스킬 폴더만 복사하면 됩니다.**

```bash
# 전역(어디서나 사용): ~/.agents/skills/  ·  특정 저장소에서만: <repo>/.agents/skills/
git clone https://github.com/KangRyun/jasoseo-plugin.git
mkdir -p ~/.agents/skills
cp -r jasoseo-plugin/skills/jasoseo ~/.agents/skills/jasoseo
```

**사용** — Codex를 작업 폴더(이력서.md가 있는 곳)에서 실행하고, 자연어로 부르면 됩니다:

```
jasoseo로 삼성전자 데이터엔지니어 자소서 초안 잡아줘
```

Codex에는 이 저장소의 서브에이전트(researcher·reviewer)가 등록되진 않지만, `SKILL.md`가 그 역할 정의(`agents/*.md`)를 따라 조사·리뷰 단계를 **직접 수행**하도록 쓰여 있어 결과는 동일하게 나옵니다. 두 역할을 Codex 서브에이전트로 따로 등록하면 더 깔끔하게 분리 실행할 수도 있습니다.

> 참고: Codex의 Skills/경로는 [공식 문서](https://learn.chatgpt.com/docs/customization/overview)를 따릅니다. 버전에 따라 경로가 바뀔 수 있으니, 위 `~/.agents/skills` 가 안 먹으면 문서에서 현행 위치를 확인하세요.

## 최근 업데이트 — v0.3.0 (2026-09-29)

공개된 IT 직군 합격 자소서 1,080건(답변 3,065개)과, 금지 규칙을 쌓아 가며 쓴 자소서를 같은 지표로 비교한 뒤 문체 규칙을 다시 썼습니다. 금지만 쌓은 글은 합격작 분포의 가장자리에 있었고(수치 밀도 98백분위, 1인칭 13백분위), 배운 점을 묻는 문항에 배움을 쓴 비율이 22%(합격작 62%)였습니다. 같은 경험을 두 규칙으로 쓴 다섯 문항을 비개발 인사 담당자 역할로 가려서 비교했더니 다섯 문항 모두 새 규칙 쪽이 뽑혔습니다. 전체 목록은 [CHANGELOG](CHANGELOG.md)에 있습니다.

- **금지는 줄이고, 범위로 잰다** — 번역투·상투어·근거 없는 교훈 명제·빈 결의는 계속 금지하되, "저는", 연결어("그래서", "그 결과"), 문항이 물은 배운 점, 업무를 지목한 포부는 허용합니다. 대신 `style_check.py`가 측정 수치·영문 용어·빽빽한 문장·문장 길이·말버릇을 합격작 범위와 비교해 경고합니다.
- **쉬운 말** — 처음 나오는 기술 용어는 하는 일을 한국어로 풀어 씁니다("CI/CD(서버 구성과 자동 빌드, 배포)").
- **문항 요구 체크리스트** — 문항이 물은 요소마다 답하는 문장이 없으면 리뷰에서 [치명]입니다.
- **비개발 독자 테스트** — 기술 배경이 없는 인사 담당자 역할로 답변을 두 문장으로 요약하게 하고, 막힌 용어와 기계적인 문장을 받아 고칩니다. 이전 버전이 있으면 블라인드 A/B로 비교합니다.
- **윤문 단계 폐지** — 외부 윤문 스킬이 "~를 통해", "또한" 같은 연결어를 걷어내 합격작 관행과 반대로 가서, 7단계를 다듬기(독자 테스트 + 범위 검사)로 바꿨습니다.
- **리뷰 등급 폐지** — LLM 심사자의 순위는 실제 서류 결과와 맞지 않았습니다. 리뷰는 사실 오류·문항 누락·가독성 결함을 찾는 데만 씁니다.
- **회사 접점은 지원동기·포부에만** — 경험 문항 본문 중간에 회사 이야기를 끼우지 않고, 마지막 계획 문장에서 공고 업무로 잇습니다.
- **소제목·본문 구성 기준** — `references/소제목_문항패턴.md` 추가(바꿔 끼우기 검사, 문단 수, 첫 문장, 문항당 경험 수).

### 이전 업데이트 — v0.2.0 (2026-09-09)

실제 지원 20여 건을 돌리며 굳어진 규칙을 옮겼습니다.

- **접점 사실표** — 기업조사 단계에서 회사의 구체 사실(시스템·발표·수치·날짜)과 내 이력서 행위를 표로 맞대어 두고, 초안은 이 표에 있는 접점만 씁니다. "귀사의 비전에 공감하여" 같은 빈 문장이 나올 자리가 없어집니다.
- **삼요소 배합** — 문항 유형별로 회사 접점·프로젝트·삶의 경험 중 무엇이 주가 되는지 정해두고, 회사 연결을 문항 끝 마무리 문장으로만 붙이는 관행을 막습니다.
- **문체 금지 4유형** — 번역투·상투어·잠언체·코다체를 금지했습니다(v0.3.0에서 범위 기준으로 개편).
- **글자 수 표준 스크립트** — `verify.py` 하나로 문항별 글자 수(공백 포함/제외 병기)와 핵심 수치 보존을 검사합니다. 개행 포함/제외가 섞여 실측이 어긋나는 문제를 없앴습니다.
- **소재 다양화·스토리 구조** — 모든 문항을 직무 경험으로만 채우지 않고, 경험 문항은 발단-위기-절정-결말-에필로그 구조를 갖추게 합니다.
- **버전 보존** — 소제목은 에이전트가 임의로 바꾸지 못하고, 최종본 수정은 `_v1.md`로 보존한 뒤 최종본 파일명을 고정합니다.

## 8단계, 이렇게 진행됩니다

| 단계 | 하는 일 | 나오는 파일 |
|---|---|---|
| 1. 기업 조사 | 미션·인재상·사업·최근 실적 조사 + **접점 사실표**(회사의 구체 사실 ↔ 내 이력서 행위) | `기업조사_<회사>.md` |
| 2. 공고·문항 분석 | 문항이 **실제로 뭘 묻는지** 분해 (복합 질문이면 하위 질문까지) → 문항 요구 체크리스트 | `자기소개.md` |
| 3. 초안 작성 | 문항별 소제목 + 본문, 컨셉 한 줄로 관통. 삼요소 배합(회사 접점은 지원동기·포부에만), 문항당 경험 수, 문체 규칙(금지 목록 + 합격작 범위 + 쉬운 말) | `자기소개서_초안.md` |
| 4. 글자 수 조정 | 제한의 95%로 실측 + 소재 중복 자가진단 | (초안 갱신) |
| 5. 전문가 리뷰 + 독자 테스트 | 인사담당자 관점 5축 평가(사실·직무·문항충실·차별성·표현), 등급 없이. 이력서에 없는 사실·근거 없는 회사 언급·문항 요구 누락·금지 문체는 [치명]. 비개발 인사 담당자 역할의 두 문장 요약 테스트 | `리뷰_리포트.md` |
| 6. 리뷰 반영 | 치명 이슈 전부·권장 대부분 반영 | (초안 갱신) |
| 7. 다듬기 | 독자 테스트에서 막힌 용어 풀어 쓰기, 기계적 문장 고치기, 범위 경고 처리, 제출용 txt (외부 윤문 스킬은 쓰지 않음) | `자기소개서_윤문.md` ← **제출용 최종본** |
| 8. 최종 검증 | 문항 수 대조, `verify.py`로 글자 수·핵심 수치 보존, `style_check.py`로 금지 0건과 범위 경고 처리 확인, 문항 요구 체크리스트 기록 | (기록 갱신) |

각 회사 폴더는 `<회사명>_마감0930`처럼 **마감일이 이름에 붙어** 생성되므로, 폴더 목록만 봐도 무엇부터 써야 할지 보입니다. 마감일이 없는 상시채용은 `<회사명>_수시`가 됩니다.

## 여러 회사 한꺼번에

"이번 주에 5개 회사 마감이야" 같은 상황이면, Claude에게 여러 회사를 한 번에 맡길 수 있습니다. 회사별로 파이프라인이 병렬로 돌아가고, 각자 자기 폴더에만 파일을 쓰기 때문에 서로 안 엉킵니다. 그냥 자연어로 "이 회사들 자소서 다 써줘"라고 하고 회사 목록을 주면 됩니다.

## 윤문 플러그인은요?

v0.3.0부터 외부 윤문(humanize) 스킬을 7단계에서 부르지 않습니다. AI 티를 지운다는 명목으로 "~를 통해", "또한", 문두 접속사를 걷어내는데, 이 표현들은 합격 자소서 답변의 절반 안팎에 나오는 평범한 연결어였습니다. 대신 `style_check.py`의 금지 목록·범위 검사와 비개발 독자 테스트로 기계적인 문장을 잡습니다.

## 자주 묻는 질문

**Q. 이력서가 PDF밖에 없어요.**
A. PDF도 읽을 수 있지만, 마크다운(`이력서.md`)으로 정리해두면 훨씬 정확합니다. "이 PDF를 이력서.md로 정리해줘"라고 먼저 부탁하셔도 됩니다.

**Q. 없는 경력을 그럴듯하게 지어내 주나요?**
A. 아니요. 그게 이 플러그인의 첫 번째 원칙입니다 — 이력서에 있는 사실만 씁니다. 부족한 역량은 숨기기보다 "빠르게 배우겠다"는 식으로 정직하게 처리하도록 설계돼 있습니다.

**Q. 글자 수가 공백 포함인지 제외인지 모르겠어요.**
A. 공고에 없으면 플러그인이 알려드리고, 제출 폼에서 직접 확인하시라고 안내합니다. 대부분 공백 포함 기준으로 맞춰두되 제출 전 확인이 필요합니다.

**Q. `/jasoseo`가 반응을 안 해요.**
A. 플러그인이 활성(enabled) 상태인지 `/plugin` 메뉴에서 확인하세요. 같은 이름의 개인 스킬이 따로 있으면 충돌할 수 있습니다.

**Q. 회사명만 넣으면 안 되나요?**
A. 됩니다 — 그러면 Claude가 직무를 되물어봅니다. 다만 처음부터 `회사명 직무` 를 같이 넣으면 한 번 덜 묻고 바로 시작합니다.
