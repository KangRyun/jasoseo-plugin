# PROFILE.md 템플릿

이 파일을 워크스페이스 루트에 `PROFILE.md`로 복사해서 본인 내용으로 채워라. 이력서(사실의 원천)와 달리, 이 파일은 "자소서를 쓸 때 반복해서 참고해야 하는 개인적 맥락"을 담는다. jasoseo 스킬은 매 지원마다 이 파일을 읽는다.

빈 항목이 있어도 스킬은 동작한다 — 처음에는 비워두고, 지원을 진행하면서 알게 된 사실을 계속 채워 넣는 방식을 권장한다.

---

## 절대 원칙 (원한다면 자유롭게 수정)

1. 자소서 소재는 이력서의 실제 경험만 사용한다. 이력서에 없는 주장·수치·경험을 만들어내지 않는다.
2. 경험 귀속을 정확히 한다. 팀 프로젝트에서 본인 담당이 아닌 부분을 "내가 했다"고 쓰지 않는다.
3. 수치는 원형을 보존한다. 같은 수치를 문항 간 중복 사용하지 않는다(소재 부족으로 읽힘).
4. 글자 수는 제한의 95%(±10자)를 채운다. 공백 포함/제외 기준을 회사마다 확인한다.
5. 초안과 윤문은 별도 파일로 관리한다. 초안은 리뷰·윤문의 원본으로 보존한다.

## 경험 귀속 주의사항

> 팀 프로젝트마다 "내가 실제로 한 일"과 "팀원이 한 일"을 여기 미리 정리해 두면, 자소서 초안 단계에서 매번 다시 확인하지 않아도 된다.

- 예: `<프로젝트명>`의 `<기술/기능>`은 팀원 `<이름/역할>` 담당 — 본인은 "학습/보조" 수준으로만 언급 가능
- 예: `<자격/기술>` 학습 이력 없음 — 기재 금지
- 예: 이력서에는 없지만 사실인 경험(`<알바/활동명>`, 기간) — 필요시 언급 가능

## 재사용 가능한 서사 자산

> 여러 회사에 지원하며 반복해서 쓸 만한 "핵심 카드"를 정리해 두면, 매번 새로 소재를 고르지 않고 회사 가치에 맞게 변주만 하면 된다.

- 핵심 컨셉 계보: (예: "데모가 아니라 운영으로 증명하는 엔지니어" → 회사 A에서는 "OO 가치" 관점으로 변주 → 회사 B에서는 "XX 가치" 관점으로 변주)
- 주력 카드 목록: (프로젝트/경험명 — 한 줄 요약 — 어떤 직무·인재상에 강하게 매핑되는지)

## 글자 수 계산 규칙

- 스크립트는 마크다운 굵게(`**`) 표기를 제외하고 `len()`으로 실측한다
- 제목(소제목) 라인 포함/제외 기준을 병기해 회사마다 어떤 기준이었는지 기록해 둔다
