# 문체 절대 금지 규칙 — 번역투·상투어·잠언체·코다체

자소서·역량기술서·면접 답변 스크립트 등 **사용자 명의로 나가는 모든 한국어 문장**에 적용한다. 초안 작성·리뷰·윤문·최종 검증 4단계 전부에서 강제하며, 위반 문장은 [치명]으로 분류해 반드시 고친다. 기계 검사는 `scripts/style_check.py`(정규식 1차 필터), 최종 판정은 아래 정의로 사람이 읽어서 한다.

## 공통 판정 기준

**"이 문장을 지우면 정보가 사라지는가, 톤만 사라지는가?"** 톤만 사라지면 그 문장은 없어야 한다. 자소서의 모든 문장은 사실(무엇을 했나)·판단(왜 그렇게 했나)·결과(무엇이 달라졌나)·구체 계획(무엇을 언제) 중 하나를 담아야 한다.

## 1. 번역투

한국어 문장 구조가 아닌 영어·일본어 직역 구조.

| 유형 | 금지 예 | 교정 예 |
|---|---|---|
| 무생물 주어 + 능동 동사 | 이 경험은 저에게 협업의 중요성을 가르쳐 주었습니다 | 이 경험 뒤로 회의 전에 인터페이스 문서를 먼저 씁니다 |
| 피동 남용 | 문제가 해결되어졌습니다 / 팀에 의해 결정되었습니다 | 문제를 해결했습니다 / 팀이 정했습니다 |
| ~에 있어(서), ~함에 있어 | 개발에 있어서 가장 중요한 것은 | 개발에서 가장 중요한 것은 |
| ~에 대한/대해 남용 | 성능에 대한 개선을 진행했습니다 | 성능을 개선했습니다 |
| ~을 가지다(관심·열정·책임감) | 데이터에 관심을 가지게 되었습니다 | 데이터에 관심이 생겼습니다 |
| ~를 통해(수단이 아닌데) | 프로젝트를 통해 성장했습니다 | 프로젝트에서 ○○를 맡으며 ○○를 익혔습니다 |
| ~로부터, ~에게 있어 | 팀원으로부터 피드백을 받았습니다 | 팀원에게 피드백을 받았습니다 |
| ~것으로 보여집니다, ~라고 생각되어집니다 | 효과가 있는 것으로 보여집니다 | 효과가 있었습니다 |
| ~의 경우, ~적인 측면에서 | 저의 경우 백엔드를 담당했습니다 | 저는 백엔드를 맡았습니다 |
| ~하는 것을 진행하다 | 테스트하는 것을 진행했습니다 | 테스트했습니다 |
| 명사 나열 + 하다 | 검증 작업 수행을 완료했습니다 | 검증을 마쳤습니다 |

## 2. 상투어

누가 써도 같은 뜻이 되는 자소서 관용구. 구체 사실로 치환하거나 삭제한다.

- 노력·태도: 끊임없이 노력, 최선을 다해, 밤낮으로, 누구보다, 항상 고민, 열정을 가지고, 책임감을 갖고, 적극적으로 소통, 능동적으로, 주도적으로(구체 행위 없이)
- 성장·경험: 밑거름, 발판, 한 걸음 더, 값진 경험, 소중한 경험, 많은 것을 배웠습니다, 성장할 수 있었습니다, 한층 성장, 시야를 넓혔습니다
- 관계·조직: 시너지, 든든한, 하나 된, 원활한 소통, 팀워크를 발휘
- 지원동기·포부: 뼈를 묻겠습니다, 평생 헌신, 최고의 전문가가 되겠습니다, 회사의 발전에 이바지, 함께 성장하는(구체 업무 없이), 미래를 선도
- 수식: 다양한, 폭넓은, 심도 있는, 체계적인, 효과적인, 성공적으로(수치 없이)

판정: 형용사·부사를 지웠을 때 뜻이 안 바뀌면 상투어다.

## 3. 잠언체(교훈 문장)

경험 뒤에 붙는 **일반화된 진리 명제**. "~은 ~이다", "~는 결국 ~에서 나온다", "~보다 ~가 중요하다", "~이라는 것을 배웠습니다/깨달았습니다" 꼴로, 주어가 '나'가 아니라 추상 개념(신뢰·준비·의지·혁신·품질)인 문장.

| 금지 예 | 교정 방향 |
|---|---|
| 준비 없는 의지는 고객 앞에서 사고가 됩니다 | 삭제. 준비했다는 사실(무엇을 언제)이 이미 앞에 있다 |
| AI의 혁신은 운영을 거쳐야 신뢰로 바뀝니다 | 삭제 또는 "배포 뒤 3개월간 오답 로그를 매주 봤습니다"처럼 행위로 |
| 품질은 모델 선택보다 데이터 구조에서 갈립니다 | "그래서 다음 프로젝트에서는 모델보다 데이터 스키마를 먼저 정했습니다" |
| 신뢰는 약속을 지킬 준비에서 나옵니다 | 삭제 |
| ~라는 것을 배웠습니다 / 깨달았습니다 / 확인했습니다 | 배운 뒤 **행동이 어떻게 바뀌었는지**를 구체 행위로 쓴다 |

에필로그(교훈) 자리는 "그 뒤로 저는 ○○할 때 ○○부터 합니다"처럼 **주어가 나이고 동사가 구체 행위**인 문장으로 채운다. 교훈을 명제로 선언하지 않는다.

## 4. 코다체

문단·문항 끝에 붙는 마무리 종결구. 앞 내용을 요약·격상하거나, 신념·결의를 선언하거나, 회사에 바치는 헌사로 닫는 문장. 지워도 정보가 사라지지 않는다.

| 유형 | 금지 예 |
|---|---|
| 신념 선언 | ~라고 믿습니다 / ~라고 생각합니다(결론 자리) / ~가 제 기준입니다 |
| 요약 반복 | 이렇게 저는 ○○을 ○○으로 바꿨습니다(앞에 이미 쓴 내용) |
| 결의·헌사 | ~하는 개발자가 되겠습니다 / ~를 ○○에서 오래 하고 싶습니다 / ~에 기여하겠습니다 / ~로 보답하겠습니다 |
| 회사 연결 격상 | 은행의 시스템 역시 ○○으로 증명되는 시스템이라고 믿습니다 / 금융 데이터를 다룰 때도 이 원칙을 지키겠습니다 |
| 대구·수사 마무리 | ○○은 ○○로, ○○은 ○○로 답하겠습니다 |

**허용되는 끝맺음**: 마지막 사실·결과·구체 계획으로 끝낸다.
- 경험 문항: 결과 수치나 그 뒤 바뀐 행동으로 끝. 예) "그 뒤로는 배포 전에 스테이징에서 같은 부하를 먼저 겁니다."
- 지원동기·포부 문항: 문항이 목표를 물으면 **무엇을·언제·어디서**가 있는 계획 문장은 허용. 예) "입행 3년 안에 상담 챗봇의 회귀 평가 체계를 맡고 싶습니다." 로열티 문장(SKILL 3단계 규칙)도 구체 업무를 지목한 이 형태로만 쓰고, "함께 성장하겠습니다"류 결의로 닫지 않는다.
- 4문항이 모두 같은 종결(~하겠습니다)로 끝나면 그 자체로 코다 반복이다.

## 적용 지점

| 단계 | 적용 |
|---|---|
| 초안(3) | 쓰면서 4유형을 만들지 않는다. 문항 끝은 사실·계획으로 닫는다 |
| 글자 수(4) | 코다·잠언 삭제로 빈 글자 수는 위기·판단·결과의 구체 사실로 채운다(톤으로 채우지 않는다) |
| 리뷰(5) | E축(표현)에 4유형 검사 필수. 위반은 [치명] |
| 윤문(7) | 에이전트 프롬프트에 이 파일 경로와 "4유형 생성 금지·발견 시 교정" 명시. 윤문 에이전트가 AI 티 해소 명목으로 코다·잠언을 **추가**하는 것도 금지 |
| 최종 검증(8) | `python3 scripts/style_check.py <파일.md>` 실행, 히트 0건 확인 후 사람이 정의로 재독 |
| 면접 답변 | 면접 답변 스크립트에도 같은 규칙. 말로 하는 답변이라 코다·잠언이 더 쉽게 붙는다 — 답변은 결과·행동으로 끝낸다 |
