# 자소서 파이프라인 (jasoseo)

## 처음 쓰는 사용자를 위한 준비물

이 스킬은 "지원자 워크스페이스" 폴더(기본값: 현재 작업 디렉터리) 안에서 작동한다. 워크스페이스에는 다음 두 파일이 있어야 한다:

1. **이력서** — 기본 경로 `이력서.md`(마크다운 권장, 없으면 PDF도 Read 가능). 모든 자소서 소재의 유일한 사실 원천이다. 파일이 없으면 사용자에게 경로를 물어본다.
2. **프로필** — 기본 경로 `PROFILE.md`. 이력서에는 안 쓰지만 자소서에는 쓸 수 있는 개인적 사실(경험 귀속 주의사항, 재사용 가능한 서사 자산, 회사별로 확립된 컨셉 계보 등)을 담는 곳. 파일이 없으면 이 스킬의 `references/profile-template.md`를 복사해 시작하라고 안내한다. 비어 있어도 진행은 가능하며, 진행 중 확인된 사실은 여기 계속 누적한다.

`<회사명>/` 폴더 하나가 지원 1건에 대응한다. **폴더는 처음 만들 때부터 마감일을 붙여서 만든다** — `<회사명>_마감MMDD`(마감일이 있을 때) 또는 `<회사명>_수시`(마감일이 없을 때, 즉 상시채용). 나중에 다시 이름을 바꾸는 수고와, 그 과정에서 기록해 둔 경로 참조가 깨지는 위험을 없앤다.

인자 해석: `/jasoseo 회사명` → 1단계부터. `/jasoseo 회사명 리뷰` → 해당 단계부터 재개.

## 시작 전 확인

1. 이미 진행된 폴더/기록이 있는지 확인 — 있으면 끝난 단계는 건너뛴다
2. 이력서·PROFILE.md를 읽는다
3. 사용자에게 받을 것: 직무명, 채용 공고(URL 또는 이미지), 문항과 글자 수(공백 포함/제외 기준 포함), 마감일

## 8단계

### 1. 기업 조사
`jasoseo-researcher` 에이전트를 호출한다(이 플러그인에 포함). 입력: 회사명·직무명·이력서 경로·공고 정보·저장 폴더 경로. 산출물: `기업조사_<회사명>.md`.

이 시점에 폴더를 새로 만든다면 마감일 접미사를 붙여서 만든다(위 "준비물" 참조).

### 2. 채용 공고 분석 + 문항 분석
- 공고 이미지나 텍스트에서 주요업무·우대사항·근무형태·마감을 확인한다
- 문항은 `자기소개.md`에 원문 그대로 정리한다. **문항이 아예 없는 공고(대개 상시채용)라면 여기서 멈추고 1단계 산출물만 남긴 채 사용자에게 "문항 없음, 기업조사만 완료"로 보고한다** — 없는 문항에 맞춰 초안을 지어내지 않는다
- **문항별 분석(반드시 수행)**: 각 문항마다 다음을 함께 기록한다
  - 실제로 묻는 것이 무엇인지 문장 단위로 분해 — 복합 질문이면 하위 질문을 모두 명시 (예: "지원동기 및 다른 지원자보다 더 잘 수행할 수 있는 이유"는 하위 질문 2개: ①지원동기 ②차별화 근거)
  - 문항 유형 분류: 지원동기 / 회사·직무 선택기준 / 성장과정·인물 / 강점·약점 / 직무적합성 / 문제해결·극복경험 / 기타
  - 이 분류·분해표는 초안 작성 후 "질문에 실제로 답했는가"를 검증하는 체크리스트로 재사용한다

### 3. 초안 작성 → `자기소개서_초안.md`
- 전체 컨셉을 한 줄로 정의한다. PROFILE.md에 재사용 가능한 컨셉 계보가 있으면 회사 가치에 맞게 변주하고, 없으면 이번 지원에서 새로 세운다
- 문항별 `**[제목: ...]**` 소제목 + 본문. 상단에 제약 요약(`>` 블록), 하단에 `## 참고`(소재 배분·미사용 소재(면접 대비)·인재상 매핑)
- 소재는 이력서의 실제 경험만 사용한다. PROFILE.md에 경험 귀속 주의사항(팀 프로젝트에서 본인 담당이 아닌 부분 등)이 있으면 반드시 확인하고 지킨다
- **지원동기 유형 문항(반드시 수행)**: 2단계에서 "지원동기"로 분류된 문항에는 로열티(장기근속·회사와 함께 성장하려는 의지)를 보여주는 문장을 담백하게 1개 포함한다. "평생 헌신하겠습니다" 같은 부담스럽고 절박한 과장 표현은 피하고, "~에서 함께 성장하고 싶습니다"처럼 자연스러운 확언 수준으로 절제한다

### 4. 글자 수 95% 조정 + 소재 중복 자가진단
- Python으로 문항별 실측(마크다운 `**` 제외, 제목 포함/제외 병기) 후 목표 = 제한 × 95% ± 10자
- **글자 수 기준(공백 포함/제외)이 공고에 없으면, 실제 지원 폼(레퍼런스 URL)을 한 번 열어보고 글자 수 카운터 표기를 확인한다.** 그래도 확인이 안 되면 공백 포함으로 가정하고 초안 상단과 참고에 "제출 전 폼에서 재확인 필요"라고 명시한다
- **소재 중복 자가진단**: 5단계(전문가 리뷰)로 넘기기 전에, 문항별로 사용한 고유 수치·프로젝트명을 목록화해 grep으로 직접 중복 여부를 확인한다. 리뷰 에이전트를 부르지 않고도 값싸게 잡을 수 있는 문제를 굳이 리뷰 단계까지 끌고 가지 않는다

### 5. 전문가 리뷰
`jasoseo-reviewer` 에이전트를 호출한다(이 플러그인에 포함, 지원 업계에 맞춰 "인사담당자 관점"으로 자동 동작). 입력: 초안·공고·기업조사·이력서(사실 대조용)·2단계 문항 분석. 산출물: `리뷰_리포트.md`.

### 6. 리뷰 반영
- [치명] 전부, [권장] 대부분, [선택] 취사 반영. 리뷰어 제안문이 이력서에 없는 새 주장을 만들면 완화해서 반영한다
- 반영 후 4단계 글자 수 재조정, 리포트와 초안 `## 참고`에 반영 내역을 기록한다

### 7. 윤문 → `자기소개서_윤문.md` (제출용 최종본)
한국어 자연스러움을 다듬는 별도 스킬(예: `humanize-korean:humanize-monolith`)이 설치되어 있으면 호출한다. 프롬프트에 명시할 제약:
- 수치·고유명사·인용 절대 불변 (구체 목록을 나열해 줄 것)
- 리뷰에서 확정한 표현 의미 변경 금지
- 문항별 글자 수 범위 유지, 원문의 문체(합니다체 등) 유지
- 출력 경로를 `자기소개서_윤문.md`로 지정, 상단 안내·`## 참고` 섹션은 그대로 복사

**해당 스킬이 설치되어 있지 않거나, 호출 후 몇 분 이상 응답이 없으면** 직접 자체 윤문(번역투·기계적 병렬·상투 표현만 다듬고 의미는 그대로 유지)을 수행해 `자기소개서_윤문.md`를 만든다. 외부 스킬의 일시적 장애가 파이프라인 전체를 막게 하지 않는다.

### 8. 최종 검증 + 기록
- 에이전트 보고를 그대로 믿지 말고 직접 재검증한다: 글자 수 스크립트 + 핵심 수치·확정 표현 문자열이 실제로 존재하는지 확인
- 사용자의 기록 시스템(메모리·노트 등)에 최종본 경로·마감·면접 대비 사항·미결 확인 사항을 남긴다
- 사용자에게 보고: 글자 수, 반영 요약, **제출 전 남은 일**(사용자 확인이 필요한 사실, 면접 대비 목록), 마감일 리마인드

## 여러 회사를 동시에 진행할 때

지원 후보가 여러 곳이고 병렬로 진행하고 싶다면, 회사별로 이 스킬 전체를 서브에이전트에 위임해 동시에 실행할 수 있다. 이때:
- 각 서브에이전트에게 이 SKILL.md와 두 에이전트 정의(`jasoseo-researcher`, `jasoseo-reviewer`) 경로, 이력서·PROFILE.md 경로, 회사별 폴더 경로를 명시적으로 전달한다
- 인덱스 파일처럼 여러 서브에이전트가 동시에 쓸 수 있는 공유 파일은 각 서브에이전트가 직접 쓰지 않게 한다. 각자 자기 회사의 개별 기록 파일만 쓰고, 인덱스에 추가할 한 줄만 반환받아 호출자가 마지막에 한 번에 정리한다
- 회사 폴더가 아직 존재하지 않는 상태에서 병렬로 시작해야 이름 충돌이 없다. 다른 프로세스가 아직 쓰고 있는 폴더는 그 작업이 끝난 뒤에 이름을 바꾼다(마감일 접미사 등)

## 테스트 시나리오

**정상 흐름**: 문항과 글자 수 제한이 명확한 공고 → 8단계 전부 실행 → 글자 수가 목표 범위 안에 들어오고 [치명] 리뷰 이슈 0건으로 수렴
**에러 흐름**: 문항이 공고에 등록되어 있지 않은 경우(대개 상시채용 공고) → 1단계(기업조사)만 수행하고 3단계 이후는 건너뛴다. 사용자에게 "문항 없음, 기업조사만 완료"로 명확히 보고한다
